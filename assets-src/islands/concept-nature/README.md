# 第六島の珊瑚庭と遠景岩礁

`../concept-art/v1/06-pearl-seabed.png` と `../concept-art/v1/PRODUCTION.md` の海底景観を参照した高詳細７モデルと、遠景専用の低分割派生３点、計10点。既存の主役モデル14点とは別の自然素材キット。

生成元は `tools/build-concept-nature.py`。Blender 5.2.1 LTS を `--background --factory-startup --python tools/build-concept-nature.py` で実行すると、10点の `.blend` 原本と単体確認用 PNG、`geometry-report.json`、`assets/islands/concept-nature.json` を再生成する。確認レンダーは固定４スレッド。`-- --first` は枝珊瑚と管スポンジの試作、`-- --preview=friendlyWhale` は指定した単体の原本・画像だけ更新する。配信には引数なしの全点生成を使う。`-- --add-far` は枝珊瑚の派生のみ、`-- --add-reef-far` は `tubeSpongeFar` と `coralBoulderFar` の２派生のみを更新する。両モードとも対象外の既存形状と材質辞書の署名を生成前後で照合し、不一致時は書き出さない。

枝珊瑚は桃色の単一材質で、インスタンス側から紫などへ色を変えられる。管スポンジの内壁は奥行きが見える暗い別材質。鯨は頭が `+X`、尾が `-X`。空中の高さは配置側が決める。静的形状は材質ごとにまとめ、位置と法線の組が同じ頂点を共有して全頂点・法線を Three.js 座標へ変換している。書き出し時に退化三角形を除き、非有限値と法線を検査する。

実レンダーは単体造形の確認であり、原画全体との絵合わせ、珊瑚庭の配置・密度、海草の動き、海中の光、歩行路、実機性能はゲーム側で確認する。

## 第六島の描画負荷を抑える配置

主路に沿う16群の庭は高詳細の形を使う。外側へ散在する小物は、枝珊瑚7,968面から2,980面、管スポンジ7,964面から2,708面、珊瑚岩11,328面から3,880面の派生へ分ける。元の輪郭、管の口と内壁、岩の粒、材質は保持し、高詳細の原本も残す。岩礁上130株にも枝珊瑚の派生を使う。2026-10-14の入口1280×720実描画は4,257,039面から3,231,509面へ約24.1％減、描画呼出しは221回から225回。これは同じ入口を描いた画面の比較で、実スマホ性能の合格を意味しない。

`src/concept-seabed.js` は小物のスポンジ・卓状珊瑚・珊瑚岩・道石と泳ぐ魚の動的影を止め、小物の地面には共有の半透明な接触影を置く。接触影は形に沿うリアルタイム影ではないため、主役の貝・鯨・岩礁の影と受影は保持する。接地の色合いと原画の雰囲気は実描画の３地点で確認した。

派生追加時の既存７形状の合成SHA-256は `cb4f1f9a24984589f89d305269f04387dc9ccd58f2cd5bec6ca536eac195ba15`、材質辞書は `d337da827e679d345063cd08be87620ea06405214fe3b5f452ec662b865aefc8`。`--add-far` は７点それぞれの形状署名を読み込み前後で照合してから書き出す。派生形状のSHA-256は `94ced536c8bea85cda2f47a94986996104c85ccd7ddf43ba317b749e0ec23f0f`。
