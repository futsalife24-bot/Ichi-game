# 次段階：子ども別プロフィールと分野別記録の設計案

2026-10-03。調査対象は codex/first-help-loop、製品HEAD 7ff05c0。これは計画であり、未承認の仕様を実装したものではない。

## 現状と最初の範囲

現在のsrc/save.jsは端末内に1人分の状態を保存する。src/quests.jsでは合計の星数から難易度を決めており、分野別の挑戦や支援の記録はない。次の改修では、プロフィール分離と観察記録を先に用意する。難易度の自動判定、島解放、誕生日、時間制限は別段階とする。

プロフィール選択→途中のお手伝いを再開→活動と支援を記録→保護者が記録を見る、を次の一周とする。子どもの画面は絵のプロフィール選択を中心にし、分野メニューは増やさない。

## 保存案

新しい版の包みに、activeProfileId、profilesを保持する。プロフィールごとにランダムなID、絵、任意の表示名、任意の出生年・月、既存のゲーム状態、分野別の観察、保護者設定を置く。日付や本名は必須にしない。登録しなくても遊べる入口を残す。外部送信は加えない。

既存ゲーム状態には星、通貨、持ち物、家具、畑、服、お手伝い進行を含め、プロフィール間で共有しない。過去の正解率・能力・分野別習熟を星から推定して作らない。

各活動の記録案は、重複防止ID、プロフィールID、分野と課題の版、提示した難しさ、選択回数、ヒントの種類と使用、手助けでの完了、完了／中断。移動タップを解答回数に数えず、無操作時間や中断を不正解にしない。「一人でできた」は自動移動や実際のヒント提示も含めて支援がなかった場合だけにする。保護者の口頭支援は検出できない限界を明記する。

初期分野は色・形・数・言葉。ひらがなは言葉の下位区分。複合活動では何を観察したかを限定し、りんごを届けたことだけで数の理解を認定しない。初回は記録のみとし、十分な観察回数や昇降条件の仮値を発達基準として扱わない。

## 既存セーブの引き継ぎ

旧v1/v2と控えはそのまま残す。保護者が既存記録の引き継ぎ先を選ぶ方式を提案中。決定前は自動移行しない。

承認後の実装では、移行元の検証→原文バックアップ→移行先の構築→保存→読み戻し検証が完了するまで切り替えない。容量不足・不正形式・将来版は停止して原文を取り出せるようにする。引き継ぎを繰り返しても記録や賞品を複製しない。

プロフィール切替は活動保存後に行い、旧画面のタイマー・音声・非同期処理を終了する。遅れて届く処理はプロフィールIDと活動IDが一致する場合だけ反映する。失敗時は次のプロフィールで続行しない。Web Locksによる同一オリジンの排他と保存失敗後の封鎖を維持する。

## 保護者画面と次の判断

当面はプロフィール、記録、バックアップを整理する。長押しは誤操作防止であり本人確認ではない。保護者用確認方式、記録保持期間・削除の扱いは実装前に決める。

難易度は将来、分野ごとに自動／固定とヒント量を設定する案。出生年月は初期の目安に限り、毎月の強制難化には使わない。変更は依頼の区切りで行い、連続した観察と変更後の観察期間で頻繁な上下を抑える。具体的な判定値は別途試作で検討する。

## 検証計画

異なる2プロフィールの所持品・進行・観察が混ざらないこと、切替後の遅延コールバック、中断と再開、同一活動の二重保存、移行再実行、保存容量不足、破損・将来版、旧キー保持、バックアップと復旧を確認する。実スマホでプロフィール選択、音声なしの案内、押しやすさを確認する。保存設計を変更する独立監査の要否は、この次段階の範囲確定時に確認する。並列作業は使わない。
