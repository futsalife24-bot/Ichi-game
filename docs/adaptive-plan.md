## 推奨する最初の範囲

保護者の記録画面に、根拠と次の遊び方の候補を表示する。保護者が採用して保存した場合だけ、次の活動から変更する。今の手動設定はいつでも使え、提案を断っても進行・賞品に不利益はない。

| 表示 | 内容 |
| --- | --- |
| 観察を続ける | 同じ種類・段階の記録が足りない。能力の評価は出さない |
| 次の設定を試す候補 | 対象の課題、現在と次の設定、根拠となる観察を表示する |
| 支援を選ぶ候補 | ヒントと一緒に完了した記録を示し、支援を続ける選択を案内する |
| 操作 | 今は変えない／設定画面で確認。自動保存しない |

最初から「苦手」「低い能力」等のラベルを付けない。ゲーム内ヒントなしでも、保護者の口頭支援は検出できないため「一人でできた」と断定しない。

## 課題ごとの観察可能性

| 課題 | 記録から分かること | 判定への制限 |
| --- | --- | --- |
| 色・形・ひらがな | 目標への到達、接触、ヒント、完了 | 移動中の偶然の接触を誤答と断定しない。目標種類・候補数・出題版の追加記録が必要 |
| 数を集める | 必要数まで集めたこと、支援の有無 | 全対象が正解なので、数の理解や正解率による難化対象から除外する。学習目標に合った別の試作が必要 |
| 鳴き声 | 指定動物への到達 | 現状の難しさ設定は出題内容を変えない。ひらがなの難化根拠へ混ぜない |

現在の形の旧設定3・4は設定2と同じ候補数、ひらがなの旧設定4は設定3と同じ文字範囲である。過去の段階番号を別々の難しさとして集計しない。ただし元の保存値を書き換えず、出題版に応じた解釈を別に持つ。

## 保存の追加案

プロフィールの game に任意の adaptationEvidence を追加する案。既存 observations と星・収集品は保持し、過去の累計から詳細履歴を作らない。新しい活動からのみ収集する。

- 課題の種類、出題版、実際の設定、目標種類と候補数、結果、対象への接触、提示した支援の種類を保存する。
- プロフィール内の活動IDで重複を防ぐ。完了・報酬・追加記録は同じ保存処理で確定し、失敗時はまとめて復元して停止する。
- 履歴は上限を設けた有限件数。提案に必要な観察幅が決まってから上限を確定する。無制限の行動ログ・絶対日時・外部送信は追加しない。
- 提案の根拠となる活動ID、提案した設定、保留／採用、採用後の観察開始位置を持つ案。同じ根拠で何度も提案しない。
- 旧データでは「観察を続ける」。未対応の将来版・破損は初期化せず、既存の書出しと復旧を使う。

## 調整の安定性

反応時間、遊ばなかった日数、中断を難化・易化の根拠にしない。自動ヒントは現状18秒で出るため、その利用だけで苦手と判定しない。聞き直しも失敗として数えない。

同じ課題種類・出題版・実設定で観察する。難しさを変えたら前の段階の履歴を次の判定に混ぜず、新しい観察を待つ。最初は一段階ずつの提案とし、変更後の再提案には新しい根拠を必要とする。易化を支援回数だけで自動実行せず、保護者が負担を見て選べるようにする。

観察回数、達成比率、再提案間隔の数値は未確定。数字を先に決めて発達基準と呼ばない。実プレイの「誰を助けるか・次の行動・終わりが分かるか」と併せて試作を評価する。公的資料の基準をこの文書で引用・主張していない。

## 実装順序と検証

1. 提案方式の確認後、必要な追加記録の種類と保持上限を具体化する。
2. 保存互換と活動IDによる重複防止を実装し、判定なしで記録を確認する。
3. 条件が説明できる課題だけで保護者向けの提案を試作する。数・鳴き声は難化対象に含めない。
4. スマホで根拠と設定変更を確認し、観察不足や支援ありでの達成を誤解しない表示へ調整する。
5. 自動調整は別途確認。島解放・誕生日の設計に判定値を流用しない。

予定するテスト：旧セーブ、複数プロフィール、同一完了の二重通知、保存失敗、再読み込み、手動設定の優先、途中変更なし、種類・段階の混在排除、観察不足、ヒント・聞き直し・中断での不当な易化なし、採用後の再提案抑制。

今回実施したのは最新コードの読取と設計の整理。製品コード・保存データ・音声を変更していない。新しい判定のテストや実機確認は未実施。任意の独立監査はユーザー方針に従い追加しない。モデルID・推論設定は未確認。
