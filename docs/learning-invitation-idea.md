# あそびのおさそい（採用・景観goal完了後に着手）

2026-10-14、本人の「オッケー。goal後のタスクとしてよろしく。」により、本人の呼びかけ案と下の追加方針を、全八島の景観制作goal完了後に進めるタスクとして採用した。作業名は「あそびのおさそい」（仮称）。現在の景観goalへ追加せず、実装はまだ始めない。遊びへの意欲や学習への効果は未検証で、頻度や選び方の細かな条件は後の設計で決める。

## 着手順序

1. 本人採用の全八島コンセプトアートに沿う景観制作goalを完了する。
2. その後、このタスクの呼びかけ・応答と自由行動・成長に合わせた遊びの選択を設計し、実装と検証へ進める。
3. 下の追加方針を島別の問題・おてつだい・景観の変化へ結びつける。第一島の簡素な練習と八島カリキュラムに沿って作る。

## 本人の案

- ログイン時に毎回、または高い確率で、子どもの成長に合う知育遊びへキャラクターが呼びかける。
- 子どもがキャラクターに話しかけるまで、吹き出しと声かけを続ける。
- 誘いに応じて遊ぶか、「自由に歩きたい」を選べるようにし、どちらからも自然に自由行動へつなぐ。
- 得意なジャンルが一つに偏る場合は、ほかのジャンルへの呼びかけ確率を上げる。

## 本人が採用した追加方針

主担当が提案した次の方向を、本人の上記回答により採用。例示した個別の遊びや景色の変化は設計時に具体化する。実装は未着手。

- 遊んだ成果で景色を少し変え、あとから見られる形で残す。例：花を３つ集めると花壇ができる、市場で果物を分類すると店が開く。
- 子どもが先生となり、キャラクターに実物を動かして教える。例：２人へおやつを分けて渡す。
- 興味のあるものを入口に別の領域へ誘う。例：虫が好きなら３匹を数える、色で分ける、大きさを比べる。
- 各島の住民が短い物語として頼む。例：海では迷子の魚に家を教える、空では風見旗を見本と同じ順番に並べる。景観の主役と活動を結びつけ、同じ問題画面だけを繰り返さない。
- 応じる場合も二つの遊びから子どもが選べるようにする。例：「おはなを ならべる／むしを かぞえる」。未経験の分野を候補に入れても、一方的に指定しない。
- 作業名は「あそびのおさそい」（仮称）、声かけの文は「いっしょに あそぼう！」を基本にする。
- 吹き出しは応答まで残し、音声は持続表示と分けて間隔を空けて呼びかける。「自由に歩きたい」を選んだら、その回の呼びかけは終える。

## 後で決める設計論点

- 呼びかけを毎回出すか確率で出すか、１回のログイン中に何度まで出すか。本人の二案を残し、頻度はまだ決めない。
- 声の再生間隔、吹き出しの持続、無音環境での表示、ほかの案内や操作との優先順。話しかけるまで案内を残す意図を保ちつつ、音声をどう繰り返すかは試作で確かめる。
- 「自由に歩きたい」を選んだら、その回の呼びかけを終える。次回ログインの再提示条件は後で決める。断っても自由行動と既存の報酬・島の進行を妨げない。
- 呼びかける遊びの候補を、現在の島・遊べる活動・手動設定・直近の遊びからどう選ぶか。別プロフィールの記録を混ぜず、選び直せる提案として扱う。
- 偏りをどう見るか。既存の観察は色・形・数・言葉の活動回数や完了、ヒント等を記録するが、能力ランクや正解率は出さない。したがって「得意」は診断名にせず、観測できる遊び方の偏りから他分野を誘う候補を考える。観察が少ない場合の扱いも未決定。
- 呼びかけが既存の難しさ設定を変えるかは未決定。まず遊びの提案と難しさの変更を分けて検討し、本人・保護者が元の設定へ戻せる方法も含めて評価する。既存の手動設定と分野別自動調整を、この案だけで変更しない。

参照：[分野別の活動記録](domain-records.md#記録すること)では観察範囲と判定の限界を定めている。[観察の保存と中断](domain-records.md#保存と中断)ではプロフィール別の保存境界を定めている。現行の難しさ選択は [遊びの設定](../src/play-settings.js) と [分野別自動調整](../src/adaptive-play.js) にあり、呼びかけの仕様とは別に扱う。[八島の学習基準](island-curriculum.md#全島共通の作成基準)では途中でやめて再開できる遊び方を基準としている。
